Основний security finding: до → причина → виправлення → після
1. Стан до. Alice могла змінити чужий інцидент Bob: PUT повертав 204, назва ресурсу змінювалася. Вразливий коміт — 65f3ce6 (рисунки 14–16, 19).
2. Причина. Сервер знаходив інцидент за ID без перевірки його власника та права поточного користувача (рисунок 78).
3. Виправлення. Ідентифікатор користувача береться з перевіреного principal; спільний метод CanAccessIncident визначає права. Список обмежено за власником, UpdateIncidentRequest приймає лише дозволені поля (рисунки 30, 74–76).
4. Стан після. Alice отримує 403 для чужого інциденту, зміни не зберігаються; дозволені дії Alice та Morgan працюють (рисунки 23–25, 32–36, 45–46).
5. Тестування. Перевірено доступ до деталей, списку, update/delete, triage, коментарів і browser client. Фінальний результат — 28/28 тестів без помилок (рисунок 83).
6. Залишкові ризики. Окремий захист cookie-authenticated змінювальних запитів від CSRF лишається на подальші роботи. За обраної політики 403 наявний чужий ресурс відрізняється від неіснуючого (404). A-11 та конкурентні зміни статусу в межах цієї роботи не перевірялися.
